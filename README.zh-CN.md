Routekeeper 是一款原生 macOS 网络体检、出口核验与实验性运行隔离工具。
它不满足于告诉你“代理已连接”，而是继续回答三个更重要的问题：

1. 当前流量实际从哪里出去？
2. 这个结果是否仍然有效，失败时会不会放行？
3. 高风险工作能否在独立文件、网络和登录环境中完成？

Routekeeper 面向个人学习、研究和技术交流，重点在可观察、可复核、失败关闭，
而不是承诺匿名、零泄漏或绕过任何服务限制。

## 为什么需要 Routekeeper

代理客户端显示“已连接”，并不等于目标流量真的走了预期路径。系统代理、TUN、
显式代理、IPv4、IPv6、DNS、应用级进程和节点出口都可能形成不同路径。

Routekeeper 把这些分散信号整理为一套可解释的证据链：

```text
观察本机路径
    ↓
比较预期出口与实际出口
    ↓
验证代理失效时是否真正断网
    ↓
为需要隔离的任务建立独立会话
    ↓
审阅变化、清理数据、保留结论
```

它不会自动修改代理客户端、订阅、节点或系统代理配置，也不会把“未检查”当作
“通过”。

## 核心流程

### 1. 观察

读取 IPv4/IPv6 路由、系统代理、显式代理、DNS、TUN 迹象和受保护进程连接，
再通过外部服务确认实际公网出口。

### 2. 验证

对比预期出口、系统路径、代理路径和外部观测结果。网络、代理、DNS、地址、
休眠唤醒或应用重启后，旧证据会自动失效。

### 3. 失败关闭

关键检查未知、过期或失败时，不进入“已保护”状态。启用代理网关保护后，
没有当前网络会话的新鲜证据就不能开启监控或启动受保护任务。

### 4. 隔离

实验性隔离为终端型任务、桌面应用和网页会话提供独立工作副本、独立 HOME、
独立日志、独立临时目录和受控网络中继。原项目只作为只读来源，不会被自动覆盖。

### 5. 审阅与清理

用户可以查看工作副本变化、文件交接请求和本机报告，并按明确归属清理缓存、
会话、浏览器配置和 Routekeeper 自有数据。

## 功能全景

| 模块 | 主要能力 |
| --- | --- |
| 概览 | 整体健康状态、保护完整度、保护范围、代理网关摘要、最近体检和待处理项 |
| 网络保护 | IPv4/IPv6、系统与显式代理路径、出口一致性、DNS、UDP/STUN、服务可达性 |
| 代理网关 | 当前路径、节点断开、代理退出、恢复后复测四阶段验证；15 分钟证据有效期 |
| 实验性隔离 | 三类运行目标、共享环境配置、独立工作副本、独立 HOME、本地中继、失败关闭 |
| 登录凭证 | 命令行工具使用 Keychain；桌面与网页登录状态独立保存、独立清除 |
| 工作副本 | 用户可见目录、变化审阅、Finder 定位、授权交接、未暂存 Git 补丁应用 |
| 清理 | 白名单扫描、归属标记、运行中保护、符号链接拒绝、普通清理进入废纸篓 |
| 运行记录 | 本机事件、连接排查、出口历史、脱敏报告和原始报告导出 |
| 界面 | 原生侧边栏、标题栏菜单、菜单栏常驻、深浅色、文字缩放、中英文界面 |
| 自动化 | 只读 CLI 自检和出口检查，支持 JSON 输出与明确退出码 |

### 网络体检

- 同时检查 IPv4 与 IPv6，不把“未启用 IPv6”误判为失败。
- 比较系统路径、代理路径、显式代理和外部服务看到的出口。
- 检查 DNS 路由、UDP/STUN 映射和目标服务 TLS 可达性。
- 识别物理 IPv6 直连风险、TUN 未确认、双栈出口不一致和出口漂移。
- 保存最近两次完整报告和最多 20 条出口历史，用于比较变化。
- 支持自动体检、连续监控、异常提醒和可选、限时的数据包头采集。

### 代理网关验证

Routekeeper 将“代理失效关闭”拆成连续阶段：

1. 当前路径能够正常访问目标。
2. 节点断开后，目标访问被阻止。
3. 代理客户端退出后，目标访问仍被阻止。
4. 恢复代理后，出口与预期目标重新一致。

只有当前网络会话取得的完整证据才算通过。代理、网络、DNS、设置、休眠唤醒、
应用重启或 15 分钟有效期变化都会使证据失效。

### 保护完整度

概览中的评分不是营销数字，而是一张可追踪的证据地图：

- 保护设置
- 本机路径
- 外部出口与服务
- 运行环境
- 代理失败关闭

未启用的可选功能不会被计为失败；证据不足、证据过期和报告不匹配也不会被
包装成高分。

## 隔离模型

实验性隔离面向三类目标：

| 目标 | 适合的任务 | 隔离方式 |
| --- | --- | --- |
| 终端型目标 | 代码、脚本、本地项目操作 | 独立工作副本、独立 HOME、终端会话、受控上游 |
| 桌面应用目标 | 图形应用、需要本地登录状态的任务 | 官方签名校验、独立 HOME、可选持久登录、受控网络 |
| 浏览器目标 | 网页操作、独立下载与登录 | 独立浏览器配置、独立下载目录、独立网络暂停/恢复 |

三类目标共享一次时区、语言、地区、代理和固定出口配置，但各自拥有独立会话。

### 文件夹边界

```text
原项目（只读来源）
    ↓ 自动复制
~/Routekeeper/Workspaces/<项目>/<会话>/workspace/
    ├── 工作副本
    └── session.json

~/Library/Application Support/Routekeeper/
    ├── Isolation/<UUID>/     # HOME、日志、控制文件、临时目录
    └── Profiles/             # 持久登录与专用浏览器配置
```

工作副本放在用户主目录中可见的位置，可随时在 Finder 打开。结束会话不会自动
把副本覆盖回原项目，也不会自动提交或推送 Git 变更。

### 网络边界

- 每个隔离会话只连接自己的本机中继。
- 上游支持本机 HTTP CONNECT、SOCKS5 和混合入口。
- 中继或上游不可用时直接失败，不回退公网直连。
- 局域网和公网直连默认关闭。
- 隔离进程不能任意监听宿主 localhost 端口，也不能自动打开默认浏览器。
- 休眠时立即断网；唤醒后重新验证，手动暂停不会自动恢复。

### 授权交接

受限任务若需要写回宿主，可以提交 JSON 清单和交付文件，而不是直接取得宿主
Git remote、SSH key、访问令牌或完整文件系统权限。

Routekeeper 会：

- 在内存中冻结请求；
- 展示文件大小、SHA256 和实际内容；
- 由用户明确接受或拒绝；
- 只保存到选择的位置，或应用未暂存 Git 补丁；
- 不自动 commit、push、发布或上传。

## 证据与失败关闭

Routekeeper 用三种状态描述结果：

| 状态 | 含义 |
| --- | --- |
| 通过 | 当前网络会话中取得了满足要求的有效证据 |
| 失败 | 检查执行完成，但结果不符合预期 |
| 未知 / 过期 | 没有足够证据，不能视为通过 |

失败关闭贯穿监控、网关、隔离启动和文件清理。进程状态无法核验、归属标记缺失、
符号链接指向未知目标或网络证据不完整时，Routekeeper 优先停止操作，而不是猜测。

## 界面与体验

- 原生 macOS 侧边栏与详情区，支持标准分栏快捷键。
- 网络保护和隔离页面使用原生标题栏菜单，操作随页面状态更新。
- 菜单栏常驻状态项，关闭主窗口后仍可继续监控。
- 浅色、深色和跟随系统外观。
- 多档文字缩放，兼容辅助功能设置。
- 简体中文、英文和跟随系统语言。
- 应用图标使用 Xcode 原生分层资源，支持当前 macOS 的玻璃材质、光照和外观变体。
- 首次启动协议确认、页面级帮助、隐私说明和风险提示。

## 快速开始

### 环境要求

- macOS 14 或更高版本
- Xcode 或兼容 Swift 5.10 的工具链
- 无第三方 Swift 依赖

### 构建

```sh
git clone <repository-url>
cd Routekeeper

swift test --scratch-path /tmp/routekeeper-build
bash scripts/build-app.sh
open dist/Routekeeper.app
```

生成本地 DMG：

```sh
bash scripts/build-dmg.sh
```

默认构建使用 ad-hoc 签名，适合本机开发与验证，不适合作为正式公共发行包。

当前测试集包含 **226 项测试**，其中 3 项需要显式环境变量才会执行联网验收；
其余测试覆盖路径证据、IPv6、报告脱敏、网关失效、隔离边界、工作副本、
会话清理、界面状态和退出确认。

## 命令行

只读自检：

```sh
dist/Routekeeper.app/Contents/MacOS/Routekeeper --self-check
```

输出脱敏出口报告：

```sh
dist/Routekeeper.app/Contents/MacOS/Routekeeper \
  --egress-audit \
  --output egress.json
```

可选参数包括目标地址、备用目标、检查间隔、跳过 DNS、跳过 UDP 和第三方 IP
情报查询。CLI 不会开启监控、修改代理设置、安装系统扩展或开始包头发送记录。

| 退出码 | 含义 |
| --- | --- |
| `0` | 请求的检查通过，或报告成功生成 |
| `1` | 参数、输出或命令执行失败 |
| `2` | 检查已执行，但报告中存在失败项 |

## 本地数据

| 数据 | 位置 |
| --- | --- |
| 应用设置 | macOS `UserDefaults` |
| 出口历史与最近报告 | Routekeeper 本机应用数据 |
| 终端工具凭证 | macOS Keychain |
| 隔离会话 HOME、日志、临时文件 | `~/Library/Application Support/Routekeeper/Isolation/` |
| 持久登录与浏览器配置 | `~/Library/Application Support/Routekeeper/Profiles/` |
| 用户工作副本 | `~/Routekeeper/Workspaces/` |
| 导出报告 | 用户选择的位置 |

Routekeeper 没有开发者运营的账号系统、遥测、广告 SDK 或自动报告上传服务。
体检会直接连接 IP 查询、STUN、DNS 和用户配置的代理上游；这些第三方可能看到
当前公网出口和请求元数据。完整数据流见 [隐私说明](PRIVACY.zh-CN.md)。

## 隐私与安全

- 默认不开启第三方 IP 情报查询。
- 终端工具凭证只写入 Keychain，不进入项目、报告、日志或交换目录。
- 报告支持脱敏导出，移除 IP、本地路径和进程标识。
- 持久登录和浏览器配置默认隔离，不会自动导入宿主浏览器的 Cookie、密码或历史。
- 清理只处理带有 Routekeeper 归属标记的白名单目标。
- 运行中的相关进程会锁定清理目标；无法核验进程时失败关闭。
- 项目工作副本、登录配置和交换目录不会被自动上传。

安全问题请不要在公开 Issue 中粘贴凭证、Cookie、完整 IP、个人路径或日志。
报告方式见 [SECURITY.md](SECURITY.md)。

## 项目结构

```text
Sources/
├── GuardCore/          # 网络证据、出口检查、隔离模型、清理与报告
├── Routekeeper/        # SwiftUI + AppKit 桌面应用、界面和会话控制
└── CAuditToken/        # 进程身份校验辅助

NetworkExtension/       # 进程级系统过滤源码与授权边界
Tests/                  # 核心逻辑、网络证据、隔离和展示测试
scripts/                # 构建、签名、DMG 与原生图标生成
docs/                   # 功能、设计、网络验收与发布说明
```

界面层使用 SwiftUI，窗口、菜单栏、标题栏菜单、Dock 图标和部分系统集成使用
AppKit。运行时网络隔离由 Seatbelt 配置、进程身份校验和本机中继共同完成。

## 当前限制

- 当前是 ad-hoc 签名开发构建，尚未完成正式签名与 Apple 公证。
- 进程级 Network Extension 过滤源码已存在，但当前 ad-hoc 构建无法激活对应系统授权。
- 实验性隔离依赖 macOS `sandbox-exec`，该接口已被 Apple 标记为弃用。
- 隔离是进程、文件和网络边界，不是虚拟机。
- 隔离不会虚拟化网卡名称、本机地址、路由和 DNS 解析器等全部宿主网络元数据。
- 隔离不会伪装硬件销售地区，也不保证服务端风控、账号状态或设备指纹结果。
- 受限目标不能监听宿主 localhost 项目端口，也不能自动启动默认浏览器。
- 工作副本不会自动覆盖原项目，Git 补丁不会自动 commit 或 push。
- Routekeeper 不会自动修改代理客户端或订阅。
- 检查结果只代表当前 Mac 和当前网络会话取得的证据，不代表零泄漏或永久有效。
