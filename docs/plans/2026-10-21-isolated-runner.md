# Routekeeper 隔离运行器实施计划

日期：2026-10-21

## 目标

为 Routekeeper 增加一个可选的隔离启动模式。Claude 进程树只访问本次会话允许的
文件范围，并且只能通过 Routekeeper 管理的本机中继联网。关闭网络后，进程保持
运行但无法绕过中继直接访问外网。

实现必须做到：

- 所选项目通过独立工作副本进入会话，原项目不会被直接修改。
- 会话只读取运行所需系统文件、工作副本、会话目录和交换目录。
- 所有网络、DNS、UDP 和 IPv6 直连在进程层被拒绝，本机中继是唯一网络入口。
- 启动自检全部通过后才显示“已隔离”；任一检查失败时不启动受限进程或明确降级。
- Routekeeper 退出、中继崩溃或用户关闭网络时，受管进程树保持失败关闭。
- 用户可以调整会话时区，不修改 macOS 系统时区。
- 用户可以审阅工作副本改动，并选择合并、导出或回滚。

## 当前边界

当前 `CredentialController.launchClaudeCode()` 直接启动 CLI，使用真实用户
`HOME`，没有外层文件或网络隔离。普通监控能够发现并协助退出所选进程，但不
阻止其读取其他文件或建立任意连接。

`NetworkExtension/` 提供可选的指定进程过滤源码，但 ad-hoc 构建不具备激活所
需系统扩展授权的条件。隔离运行器不能把该源码的存在当作已经启用保护。

Apple 的 `sandbox-exec` 和 `sandbox_init` 均已标注为 deprecated。macOS 27
仍允许自定义 profile 限制文件与网络，但 Apple 不提供稳定的公开 profile API
承诺；旧的命名预置 profile 在 SDK 27 上会被终止。隔离运行器必须把它视为可
替换的实验性执行层，并在每次启动时自检。

## 关键决策

1. 不自行实现内核级沙箱。Routekeeper 负责编排 Apple 提供的进程限制、文件权限、
   本机中继、监控和恢复。
2. 第一版采用每次启动生成的动态 `sandbox-exec` profile。配置失败、命令缺失或
   关键自检失败时进入失败关闭，不退回普通启动并显示“已保护”。
3. 本地中继使用随机回环端口与随机会话凭据，支持 HTTP CONNECT 和 SOCKS5。
   上游先适配现有 Clash mixed、V2Ray HTTP/SOCKS 和 Shadowsocks 客户端提供
   的本机 SOCKS 端口，不在第一版自行实现所有代理协议。
4. 项目使用写时复制的工作副本。优先使用 APFS `clonefile`，不可用时回退到普
   通复制；会话结束后生成差异供用户审阅，未确认前不回写原项目。
5. 网络访问默认限制到应用运行所需域名。只有用户明确授权时，才允许工作副
   本中的工具访问额外目标。
6. 会话级环境使用独立 `HOME`、缓存、临时目录和 `TZ`。不改系统时区、语言、
   字体或浏览器全局配置。

## 实施单元

### 1. 隔离模型与资源生命周期

- 新增 `Sources/GuardCore/IsolationModels.swift`：定义会话状态、选中项目、
  交换目录、时区、网络策略、创建/运行/结束状态和错误分类。
- 会话根目录固定在 Routekeeper 应用支持目录下的随机 UUID 路径，禁止用户提
  供任意路径覆盖会话根目录。
- 清理只删除本次会话拥有的路径；原项目、用户下载目录和系统缓存不在删除范围。

验收：取消创建、复制失败、应用退出和崩溃恢复都不会留下“正在运行”假状态。

### 2. 安全启动器

- 新增 `Sources/Routekeeper/SandboxSession.swift`，负责准备目录、生成 profile、
  启动进程、追踪进程树和回收资源。
- profile 使用 `-D` 参数或私有临时 profile 文件传入路径，禁止把用户路径拼接
  成未转义 shell 命令。
- 子进程继承限制；需要启动 shell 时直接包含在受管进程树中。
- macOS 不支持、命令失败、profile 被拒绝或自检失败时终止本次启动并记录原因。

验收：同一会话内由应用启动的二级、三级子进程也无法读取范围外文件或直连网络。

### 3. 工作副本与交换目录

- 新增项目准备器：检测 Git/非 Git 项目，优先使用 APFS 克隆，失败时使用有进度
  和空间预检的复制。
- 工作副本与交换目录是唯一可写用户路径；系统目录保持只读。
- 会话结束时计算文件变更并展示新增、修改、删除列表；用户可导出补丁或复制回
  原项目，默认不回写。

验收：原项目在会话期间保持不变；用户拒绝合并后仍可从会话目录恢复改动。

### 4. 本机中继与代理适配

- 新增 `Sources/Routekeeper/LocalRelay.swift`，监听 `127.0.0.1` 的随机端口。
- 支持 HTTP CONNECT 与 SOCKS5 客户端入口，按本次会话凭据拒绝其他本机进程。
- 上游连接仅允许到启动时验证过的本机代理端点；切换上游必须结束当前会话。
- 维护目标域名策略、连接计数、失败原因和当前活跃连接；不保存 payload。
- 中继停止时关闭 listener 和活跃连接，并让启动器触发网络关闭状态。

验收：直连公网 IP、DNS、UDP、IPv6 和 QUIC 均失败；经允许目标域名的请求能从
中继连接；停用网络后已有和新建连接立即失败。

### 5. 启动前与运行中自检

- 新增 `Sources/Routekeeper/IsolationPreflight.swift`。
- 在受限子进程中验证：系统运行时可用、工作副本可写、交换目录可写、范围外文件
  不可读/写、直连 DNS 和公网失败、中继目标成功、子进程继承限制、时区符合选择。
- 检查系统版本、`sandbox-exec` 存在性、profile 应用结果和中继健康状态。
- 运行中周期性确认中继 listener、代理上游、进程树与关键文件仍处于预期状态。

验收：未知、超时和部分成功都不能作为通过；失败后界面不会显示“已隔离”。

### 6. 监控、断网与恢复

- 显示进程树、文件变更、中继目标、拒绝事件、出口地址和当前时区。
- “关闭网络”执行一次性失败关闭；“恢复网络”重新建立 listener 并执行自检。
- “结束会话”先停止中继，再按 PID、启动时间和路径确认后终止受管进程树。
- 应用崩溃恢复时先判断旧 listener 和进程是否存活，禁止直接复用旧会话状态。

验收：强制结束中继、代理上游或 Routekeeper 后不会回落直连；恢复需要明确操作。

### 7. 界面与文案

- 新增“隔离启动”页面和会话详情页，状态使用“检查中 / 已隔离 / 网络已关闭 /
  失败关闭 / 已结束”。
- 首次使用说明会复制项目、可能增加磁盘占用、`sandbox-exec` 的实验性质和不
  修改系统时区。
- 自检结果直接解释普通用户能做什么，技术细节放在可展开区域。
- 免责声明、关于页和主界面保持现有视觉语言，不在仓库 About 元数据中填写描述。

验收：用户不阅读源码也能判断文件实际位置、网络是否开启、如何合并改动和如何
完全退出。

### 8. 测试与交付

- 单元测试覆盖路径校验、profile 参数、代理握手、目标策略、状态机和毒化输入。
- 集成测试使用临时目录和本机测试服务器，不访问真实账号、订阅或代理密钥。
- 在至少一个最低支持系统和一个当前系统上验证；Apple 修改行为时自动禁用并给
  出原因。
- 交付前执行完整测试、Release 构建、ad-hoc 签名、DMG 验证和自检演示。

## 已知风险

- Apple 可随时改变或移除未公开的 sandbox profile 行为。
- 受限进程仍可修改工作副本和交换目录，也可把允许目录内的数据发送给允许目标。
- 通用代理目标白名单需要维护，过窄会影响工具链，过宽会扩大外传面。
- 应用级代理配置可以被忽略，因此必须依赖进程级网络拒绝，不能只设置环境变量。
- 固定出口地址不能证明服务端账号状态，也不能覆盖 WebRTC、字体、GPU 和历史行为
  等服务端关联信号。
- 自研代理协议适配会增加凭据处理和升级风险；第一版优先调用用户已有本机代理。

## 完成标准

- 文件范围外读写、直接 DNS、直连 IPv4/IPv6、UDP/QUIC 和网络关闭后连接均有自
  动化或可重复的实机证据。
- 子进程继承限制，切换项目、代理或时区不会复用旧策略。
- 原项目未被直接修改，用户可审阅并回滚工作副本。
- `sandbox-exec` 不可用或被系统拒绝时，应用明确失败关闭并保留可诊断日志。
- 中英文界面、README、免责声明和风险说明准确，不把实验性隔离描述为 Apple
  认证或绝对安全。
