# 代理网关独立验证（0.3.12）

## 目标

代理客户端或外部 Agent 负责修改实际代理配置，Routekeeper 独立复测结果。
Routekeeper 不内置 Agent，不自动修改代理，也不执行 Agent 生成的任意命令。

## 用户流程

1. 在“保护 → 高级网络保护”选择“分流保护”或“仅限制 Claude”。
2. 复制对应提示词给现有 Agent，由 Agent 核对客户端、内核、节点和配置能力。
3. 在“网络体检 → 代理网关检查”检查当前代理路径。
4. 只停用所选海外节点，保持代理客户端运行，复测 Claude 是否断网。
5. 恢复节点，完全退出代理客户端，复测 Claude 是否仍能直连。
6. 重启代理并恢复节点，完成恢复后的路径复测。

四项通过后才显示“当前代理网关已验证”。节点断开、代理退出和恢复动作由用户或
外部 Agent 完成，Routekeeper 只观察结果。

## 证据

- 系统代理入口或 TUN 路由。
- ipinfo.io 与 Claude 跟踪地址的出口一致性。
- 显式系统代理路径。
- IPv4 与可用 IPv6 的独立出口。
- 系统 DNS 路由和有效响应。
- UDP/STUN 参考项。
- 节点断开时 Claude 目标不可连。
- 代理客户端退出时 Claude 目标不可连。
- 恢复代理后必需路径重新通过。

必需项必须全部通过。参考项失败不会伪造严格结论。

## 失效条件

- 网络路径、系统代理、DNS 或地址变化。
- 休眠或唤醒。
- 保护设置变化。
- Routekeeper 重启。
- 超过 15 分钟。

处于手动节点断开测试时，网络变化会把流程推进到当前应执行的下一项测试；
恢复后的最终证据会清除这次变化标记。已经完成的验证在变化后不能继续作为门禁依据。

## 安全边界

- 不读取或保存订阅、节点名称、控制密钥、代理密码或原始配置。
- 不保存出口 IP，只保存脱敏的检查结果。
- 不能证明代理客户端按进程识别了每个 Claude 子进程。
- 不能证明账号安全、设备指纹或服务端风控结果。
- 实验性进程沙箱始终保持自己的进程和网络预检，不以网关状态替代。
