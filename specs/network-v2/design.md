# 实现设计

- GuardCore：兼容解码设置；双栈路由与出口；代理适配；带事务校验的 STUN；全局 DNS 服务器的路径及实际查询；unknown 状态阻止放行。
- UI：复用保护设置，新增另一地址族目标、适配器、轮询时间、附加探测开关；独立的高级保护页面管理系统扩展及抓包，不绑定监控开关。
- 事件：NWPathMonitor + SCDynamicStore + NSWorkspace 睡眠通知。事件使 epoch 递增，旧异步结果不能复用，立即异常锁定，延时合并事件后重新检查。
- 可选扩展：NEFilterDataProvider 为已识别的选定应用（含明确 Node CLI 脚本入口）拒绝外部 socket，只允许连接用户确认的本地 HTTP 代理。此模式要求客户端明确使用本地代理，会阻止依赖直接 TUN 的客户端连接。不会过滤代理自身的上游连接，因而不保证代理自身防泄漏。按进程归属匹配，不能覆盖未知子工具。普通本地版本只提供可用性诊断和签名构建入口。
- 抓包：按目标 IP 的当前路由自动选择物理或 tunnel 接口，执行有界 tcpdump 文本捕获，过滤并导出包头记录；不抓 payload、不自动断代理、不输出自动通过。外部目标、时间范围与人工测试步骤必须纳入验证判断。
- 验证：纯策略与协议畸形包、设置迁移、网络事件过期结果、代理识别边界；构建 App 和扩展。实机签名安装/断代理/抓包与开发构建验证分开报告。
