# 网络保护第二版

1. 当执行检查时，系统应分别探测 IPv4/IPv6 的路由、系统路由出口和显式代理出口；可用地址族必须匹配用户确认的相应固定目标。无路由仅表示本轮未发现，不能保证永久不可用。
2. 当启用 DNS/UDP 探测时，未知结果应阻止开启监控；有效 UDP 响应必须匹配目标。用户可关闭这些附加探测，界面应显示未验证。
3. 当发生休眠、唤醒、路径、DNS、代理或地址变化时，系统应立即作废旧结果；正在保护时进入异常锁定，唤醒/变更后重新检查而不自动解除锁定。
4. 当用户选择 FlClash、Clash Verge、mihomo 或自动识别时，系统应核验对应进程，继续要求系统代理及路由/出口证据。不得读取订阅和凭据。
5. 当用户设置 1–300 秒轮询间隔时，系统应在每轮结束后等待该时间；默认 2 秒，不重叠轮询。旧设置应可迁移。
6. 当用户主动启用网络扩展时，只约束选定的 Claude 桌面/Code；启用前需退出所选进程，清除已有连接。签名/entitlement/系统批准不足时应显示不可用，不宣称已阻断。
7. 当用户启动可选抓包验证时，应确认接口、目标、限时与敏感信息提示；不自动制造代理故障，不把无数据判成通过，不影响其他应用的网络配置。

用户已选择按应用强制阻断，不接受全机防火墙方案。开发机器没有有效代码签名身份，真实系统扩展激活与故障验证需要签名交付和本机授权环境。
